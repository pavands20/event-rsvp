<!-- sdlc:auto:start overview -->
Event RSVP is a demo application for publishing events and collecting guest RSVPs without requiring guests to create accounts. It is a monorepo with two apps: a React 19 + Vite SPA frontend that currently runs on seeded sample data, and a FastAPI 0.115 backend that ships with only a health-check endpoint. The backend uses SQLAlchemy with a SQLite default database (PostgreSQL 16 is the intended production database) and creates tables from models on startup. The frontend was generated from an approved design and includes unit tests (Vitest), e2e tests (Playwright), ESLint, and Prettier.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js 20+
- Python 3.12+
- pip
- Docker and Docker Compose (optional, for PostgreSQL via docker-compose.yml)

<!-- sdlc:auto:start setup -->
1. cd backend && pip install -r requirements.txt
2. cd frontend && npm install
3. Optional: docker compose up -d to start a local PostgreSQL 16 instance
4. cd backend && uvicorn app.main:app --reload to start the API on port 8000
5. cd frontend && npm run dev to start the Vite dev server on port 5173
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend follows a per-component router pattern: one router per architecture component that owns endpoints (currently empty under backend/app/routers/).
- Backend stub routes return a typed StubResponse (endpoint, status='not_implemented') so the OpenAPI document stays complete while handlers are unwritten.
- Backend uses SQLAlchemy 2.0 declarative models inheriting from a shared Base; tables are created via Base.metadata.create_all on startup (no Alembic migrations yet).
- Default database is SQLite (sqlite:///./app.db) unless DATABASE_URL env var is set; PostgreSQL 16 is the intended production database.
- CORS is configured via ALLOWED_ORIGINS env var (comma-separated); falls back to Vite dev origins (localhost:5173, 127.0.0.1:5173) when unset.
- Backend code style enforced by ruff (ruff.toml); pytest configured via pytest.ini with pythonpath='.' and testpaths='tests'.
- Frontend uses path alias '@' mapped to './src' in both vite.config.ts and tsconfig.json.
- Frontend screens render seeded sample data; the API client in src/lib/api.ts is the seam to wire screens to real endpoints.
- Frontend API client sends a Bearer token from localStorage (session_token) or a build-time API_SECRET_KEY on every request.
- Vitest test files scoped to src/**/*.{test,spec}.{ts,tsx}; Playwright specs live in e2e/ and are excluded from Vitest collection.
- The Dockerfile runs the app as an unprivileged user (appuser, uid 10001) with a health check on /health.

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Backend pytest cannot import the app package | Run pytest from the backend/ directory; pytest.ini sets pythonpath='.' so 'import app' resolves correctly. |
| Frontend dev server cannot reach the backend API | Ensure the backend is running on port 8000. The API client defaults to http://localhost:8000; override with VITE_API_BASE_URL at build time. |
| CORS errors when the frontend calls the API | Set ALLOWED_ORIGINS env var on the backend to include the frontend's origin (e.g. http://localhost:5173), or rely on the built-in dev defaults. |
| Playwright e2e tests fail because the backend isn't running | Playwright auto-boots the backend from ../backend/.venv; ensure dependencies are installed there first, or set E2E_BASE_URL to test against a deployed instance. |
| Playwright browser not installed | Run 'npm run test:e2e:install' to fetch Chromium before running e2e tests. |
| Frontend build succeeds but typecheck fails | Run 'npm run typecheck' to see errors; the build intentionally skips type checking, so fix tsc errors before maintaining the codebase. |
